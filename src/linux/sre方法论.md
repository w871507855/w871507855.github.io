# SRE 方法论学习目录（标题 + 练习题）

## 第一部分：SRE 理念与定位

### 1. SRE 概述与核心理念
- 1.1 SRE 的起源（Google）与定义：用软件工程方法解决运维问题
- 1.2 SRE 与传统运维（Ops）、DevOps 的关系与区别
- 1.3 SRE 的核心原则：拥抱风险、服务等级目标、消除辛劳、自动化、全局视角
- 1.4 50% 工程时间原则的含义与落地
- 1.5 SRE 在不同规模团队中的组织形式
- **练习**：用自己的话写一段 200 字说明“SRE 与传统运维最大的区别是什么”，并举一个你当前工作中的 Toil 例子

### 2. 可靠性目标体系：SLI / SLO / SLA
- 2.1 SLI（服务质量指标）的定义与选取原则
- 2.2 常见 SLI 类型：可用性、延迟、吞吐量、错误率、饱和度
- 2.3 SLO（服务等级目标）的设定方法与合理性
- 2.4 SLA（服务等级协议）与 SLO 的关系及法律/商业含义
- 2.5 从用户视角定义 SLI（而非从系统视角）
- 2.6 内部 SLO 与外部 SLA 的差异管理
- **练习**：为一个 Web API 服务定义 3 个 SLI（可用性、P99 延迟、错误率），并为每个 SLI 设定一个合理的 SLO 目标值，说明理由

### 3. 错误预算（Error Budget）
- 3.1 错误预算的概念：100% - SLO = 允许的失败空间
- 3.2 错误预算的计算方法（按时间窗口折算）
- 3.3 错误预算的消耗与燃尽率（Burn Rate）
- 3.4 错误预算策略：预算充足时加速发布，预算耗尽时冻结变更
- 3.5 多窗口燃尽率告警（1h / 6h / 3d）
- 3.6 错误预算与产品、开发团队的协作机制
- **练习**：假设某服务 SLO 为 99.9%（30 天窗口），计算每月允许的不可用时间；再设计一条“1 小时燃尽率超过 14.4 倍”的告警规则思路

### 4. Toil（辛劳）的识别与消除
- 4.1 Toil 的定义：手工的、重复的、可自动化的、无持久价值的、随规模线性增长的工作
- 4.2 Toil 的识别方法与量化（时间占比统计）
- 4.3 Toil 消除的优先级排序
- 4.4 自动化的投入产出评估
- 4.5 从 Toil 到平台能力的演进路径
- **练习**：列出你日常工作中的 5 项任务，逐项判断是否为 Toil，并按“自动化收益/成本”排序，选出最该先自动化的一项

## 第二部分：故障管理与复盘

### 5. 事件响应与 On-Call
- 5.1 事件分级（Sev1 / Sev2 / Sev3）与响应流程
- 5.2 On-Call 轮值制度与负载均衡
- 5.3 事件指挥（Incident Commander）角色与职责
- 5.4 沟通机制：状态页、战情室、升级路径
- 5.5 减少告警疲劳与 On-Call 负担
- **练习**：为一个假设的“核心 API 5xx 突增”事件，写出从告警触发到恢复的分级响应流程（谁做什么、多久升级）

### 6. 无指责复盘（Blameless Postmortem）
- 6.1 复盘的目的：改进系统而非追责个人
- 6.2 复盘文档的标准结构（时间线、影响、根因、改进项）
- 6.3 根因分析 vs 贡献因素分析
- 6.4 5 Whys 与故障树方法
- 6.5 改进项的跟踪与闭环
- 6.6 复盘文化的建设与常见误区
- **练习**：针对一次“磁盘写满导致服务不可用”的故障，写一份完整的复盘文档（含时间线、影响范围、根因、3 条可落地的改进项）

### 7. 变更管理与发布安全
- 7.1 变更风险评估与变更窗口
- 7.2 灰度发布、金丝雀发布、蓝绿部署的可靠性视角
- 7.3 发布回滚策略与自动化
- 7.4 变更与错误预算的联动（预算不足时限制变更）
- 7.5 配置变更与代码变更的同等风险对待
- **练习**：设计一个“新版本发布”的变更流程，说明在错误预算充足与耗尽两种情况下分别如何调整发布节奏

## 第三部分：容量与韧性

### 8. 容量规划与资源管理
- 8.1 容量规划的基本方法：基于历史趋势与业务预测
- 8.2 负载模型与峰值估算
- 8.3 资源利用率与成本平衡（避免过度预留）
- 8.4 弹性伸缩（HPA/VPA）与容量兜底
- 8.5 容量评审与扩容决策流程
- **练习**：根据某服务过去 3 个月的 QPS 增长趋势，估算下季度所需副本数与资源，并写出扩容决策依据

### 9. 混沌工程与韧性验证
- 9.1 混沌工程的理念：主动注入故障验证系统韧性
- 9.2 混沌实验的设计原则（假设、范围、爆炸半径控制）
- 9.3 常见故障注入类型（网络延迟、Pod 杀死、磁盘满、依赖超时）
- 9.4 混沌工具简介（Chaos Mesh、Litmus）
- 9.5 从混沌实验到改进闭环
- **练习**：设计一个“模拟某依赖服务超时”的混沌实验，写出实验假设、注入方式、观察指标与预期结果

### 10. 依赖管理与降级设计
- 10.1 依赖梳理与关键路径识别
- 10.2 超时、重试、熔断、限流的设计原则
- 10.3 降级策略与兜底方案
- 10.4 单点故障识别与消除
- 10.5 多活与容灾的基本思路
- **练习**：为一个“依赖第三方支付接口”的订单服务，设计超时、重试、熔断与降级策略，并说明各参数取值理由

## 第四部分：工程效率与协作

### 11. 自动化与平台工程思维
- 11.1 自动化的层次：脚本 → 工具 → 平台 → 自助服务

- 11.3 运维能力的 API 化
- 11.4 减少人工审批与流程瓶颈

### 12. 跨团队协作与可靠性推广

- 12.2 可靠性评审（Production Readiness Review）

- 12.4 可靠性文化的推广与培训
